# 随身 AI · Pocket Local Assistant

Android 本地 AI 助手。把屏幕观察、本地模型与功能模块分开，后续可扩展新的手机辅助功能。

**状态：实验版。已在连接的 vivo V2302A / Android 16 手机上验证本地 OCR、模拟播放器连续换节、验证提示暂停，以及推荐模型加载和简单问答；尚未证明任何课程平台能稳定连播。具体记录见 [VALIDATION.md](VALIDATION.md)。**

## 首版功能

- **本地问答**：LiteRT-LM 在手机 CPU 上运行 `.litertlm` 模型，支持问答、整理与最近屏幕文字总结。没有云端推理接口。
- **本地屏幕识别**：APK 内置中文 ML Kit OCR。每 4 秒检查一次所选应用，屏幕图像只在内存中处理。
- **课程播放辅助**：根据屏幕上的真实播放时间推进、结束提示与明确的下一节按钮进行有限连播。单帧、目录里的“已完成”、模型猜测都不能触发换节。
- **目录连播（0.1.7，实验）**：针对知到竖屏“教程 / 课程提醒”布局，读取绿色当前小节、编号和可见行末图标。默认跳过右侧带 √ 的已完成小节，只选择明确的未完成播放按钮；看不清图标或中间目录不连续时等待。当前节未完成时，确认实际播放结束后才切换，并等待高亮变化。
- **统一控制**：目标应用选择、可拖动的开始/暂停/停止浮窗、媒体静音、状态记录、模型下载/导入/卸载。
- **中断恢复**：模型与更新下载可暂停续传，网络中断保留进度；切换页面和旋转屏幕保留当前问答。问答内容仅保留在进程内，结束进程后清除。
- **App 内更新**：在“模型”页面检查 GitHub 正式版本、下载 APK，经 SHA-256、包名、版本与签名校验后唤起系统安装。

## 使用

1. 安装 Releases 中的 ARM64 APK，Android 11 及以上。
2. 在应用里选择目标应用。按页面说明在系统无障碍设置开启“随身 AI 屏幕助手”。
3. 点击“准备目录连播浮窗”，浮窗此时暂停等待；进入课程并开始视频，再点浮窗“开始”。也可从正在播放的课程切回助手准备浮窗，然后从最近任务回到原课程页。准备浮窗不会重新打开目标应用。知到竖屏目录让绿色当前节与紧邻的下一节同时可见；提供明确“下一节”文字按钮的播放器选择“课程播放辅助”。
4. 本地 AI 单独在“模型”页下载推荐的 Qwen3 0.6B（约 585 MB），或导入兼容的 `.litertlm` 文件；点击“加载模型”。GGUF 不兼容。
5. 在“本地 AI”页输入问题，可附带最近识别的屏幕文字。识别结果可能有误，请核对。

初次模型下载和主动检查/下载更新需要联网；推理与屏幕识别可以离线。可选择 Hugging Face 源站或第三方 `hf-mirror.com` 镜像，均校验相同固定 SHA-256。下载时保持本应用前台；暂停、连接中断或进程重启后再次点击下载可继续。服务器不支持续传时会从头下载，完成后仍需哈希校验。不会静默安装更新，安卓仍要求本人确认。

## 能力边界

这是屏幕文字识别与本地文字模型的组合，不是完整视觉语言模型。课程应用必须亮屏并处于前台；切换其他应用、锁屏、截图受保护、控件不可见都可能停止工作。它不能和同一手机全屏游戏同时操作。

通用课程模块需同时提供可识别的播放时间或明确结束提示，以及唯一的“下一节/下一集/下一个视频”按钮。目录模式只处理知到已识别的竖屏教程布局，使用无障碍可见控件边界定位行末图标，再在本机分析截图像素区分勾号、播放三角和播放中状态；不读取图标背后的内部学习数据。当前绿色标题、目标和中间所有目录行必须同时可见；需要时请手动滚动或展开。横屏、图标被遮挡、编号缺失和页面改版会停止切课。两种模式都不会拖动进度条或推算学习已完成。

遇到验证码、身份验证、异常脚本提示、题目、考试、支付等状态会暂停，由本人处理；不关闭或绕过平台提示，不代答/代考，不修改学习进度、不模拟完成接口，也不保证平台接受学习记录。停止助手不等于自动暂停第三方播放器，请在播放器中确认。

iQOO 8 Pro 是最初适配意向，具体性能需实机测试。默认 CPU 双线程，最大 2048 token 上下文，单次最多输出 384 token。热状态达到 Android 严重级别时屏幕观察暂停；没有硬件实测前不承诺温度和速度。

## 开发

JDK 17、Android SDK 36、Gradle 8.14.3、AGP 8.13.2、Kotlin 2.4.0。依赖版本固定。

```sh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

`core/AssistantModule` 接收结构化 `ScreenFrame` 并返回 `Wait / Pause / Tap`；在 `ModuleRegistry` 注册新模块。只有执行层拥有触控权限，执行前重新检查前台包名和会话编号。新增模块需覆盖状态转换与误触测试。未来图像模型可通过新模型后端接入，不需要改写模块注册结构。

推荐模型来自 [LiteRT Community Qwen3-0.6B](https://huggingface.co/litert-community/Qwen3-0.6B)。文件 SHA-256 固定为 `c5f39b4191926786c3e6668b62af4d6eb15248dfc7a5348252a9b406f33f2108`；模型仓库内容变化时会拒绝替换，需发布新的校验值。模型及其转换版本的许可证独立于应用。

## 发布与升级

正式 APK 必须持续使用同一私有签名密钥。密钥不进仓库。构建环境使用 `POCKET_SIGNING_STORE` 与 `POCKET_SIGNING_PASSWORD`；别把发布密钥写入源码。调试版和正式版签名不同，不能互相覆盖升级。

每次正式发布添加 `update.json` 与 `pocket-local-assistant-VERSION-arm64.apk`。清单由 `scripts/make_update.py` 生成，客户端还会验证安装签名。模型保存在应用私有目录，正常覆盖安装保留；卸载会删除。

## 隐私与许可证

不主动访问密码、浏览器会话或其他应用私有文件；屏幕上可见的文字按你授予的权限处理。屏幕图像不落盘，最近识别文字和最多 80 条状态记录仅留内存；目标应用选择保存在本机。应用未自行添加广告或分析服务。

主动检查 GitHub 更新和下载模型需要联网，相关服务器会收到常规请求信息。**第三方 ML Kit SDK 会向 Google 发送性能与使用指标，并可能请求模型或兼容性更新；屏幕图像、输入文字与识别结果仍在设备内处理，不由 ML Kit 发往 Google。** 详情见 [ML Kit 隐私说明](https://developers.google.com/ml-kit/terms)。断网时，本地识别和已经安装的模型仍可使用。

应用源码采用 MIT；依赖及模型见 [THIRD_PARTY.md](THIRD_PARTY.md)。
